# Synthetic rare-format originals

These tiny files contain invented sine tones, generated locally for the import
matrix. They contain no downloaded recordings, personal music or provider data.
The test helper copies them before adding tags. The encoder programs, source
archives and compatibility runtime are not shipped and are not test dependencies.

`music_import_formats.import_tone` generates the other formats with FFmpeg and
generates a complete synthetic DSF stream directly. The native acceptance test
verifies complete original downloads, raw streams and decoding for each accepted
fixture. TAK is a separate native rejection canary.

## Tools and reproduction

The source WAV is stereo signed 16-bit PCM, 44,100 Hz, 0.3 seconds at 523 Hz,
generated by FFmpeg 9.0.2:

```sh
ffmpeg -v error -nostdin -y -f lavfi \
  -i sine=frequency=523:sample_rate=44100 -ac 2 -t 0.3 \
  -map_metadata -1 -c:a pcm_s16le tone.wav
```

Its SHA-256 is
`ed129559807ebcf7d6e92bb65d163f926168f168769a6220346dba9b083291b1`.

- **APE:** the author's [Monkey's Audio SDK](https://monkeysaudio.com/developers.html),
  version 13.27, archive `MAC_1327_SDK.zip`, SHA-256
  `c47c6b36f6a7bd50d990f2eb36a70915c0074a7b9634be396c94464905e76686`.
  Build with `cmake -S SDK -B build -DCMAKE_BUILD_TYPE=Release` and
  `cmake --build build -j 4`; run `build/mac tone.wav tone.ape -c2000`.
- **Musepack:** existing `mpcenc` 1.30.1, based on the
  [Musepack tools](https://www.musepack.net/index.php?pg=src).
  Run `mpcenc --silent tone.wav tone.mpc`.
- **Shorten:** version 3.6.1, [MacPorts source archive](https://distfiles.macports.org/shorten/shorten-3.6.1.tar.gz),
  SHA-256 `ce22e0676c93494ee7d094aed9b27ad018eae5f2478e8862ae1e962346405b66`.
  Configure and build only in scratch space:
  `./configure --prefix=/tmp/synthetic-shorten && make -j 4`.
  Run `src/shorten tone.wav tone.shn`; it appends its default seek table.
- **TAK:** the author's [TAK 2.3.3 archive](http://www.thbeck.de/Download/TAK_2.3.3.zip),
  SHA-256 `40d26992266f1377d576b88b84b88d2ab256dc321e47f90314402a80692aba6a`.
  In a new, isolated CrossOver 26.3.0 `win10_64` bottle, run
  `Takc.exe -e -v -silent tone.wav tone.tak`.
  The author's encoder verifies the frames and FFmpeg fully decodes them, but the
  pinned default Navidrome scanner rejects both tagged and untagged copies.
- **Ogg Speex:** existing `speexenc` 1.2.1. Generate the same WAV at 32,000 Hz,
  then run `speexenc tone-32000.wav tone.spx`. Tests exercise both `.spx` and `.ogg`
  names. See the [Speex tools](https://www.speex.org/downloads/).

FFmpeg and ffprobe were both 9.0.2; Mutagen was 1.48.1. The native server was the
test harness's SHA-256-pinned unmodified Navidrome 0.64.2 Darwin ARM64 binary.
The tested `Scanner.Extractor=ffmpeg` setting logs that the extractor is missing,
falls back to TagLib and still skips TAK. This is not conditional TAK support.
The same 53-original matrix also passes with the SHA-256-pinned Linux ARM64
Navidrome 0.64.2 binary, Debian FFmpeg/ffprobe 5.1.9 and Mutagen 1.48.1.
The separate TrueAudio matrix generates tagged/untagged `.tta` with FFmpeg's
`-c:a tta`: Linux imports both through native download/raw stream and full decode
(55 accepted originals across 24 extensions in total). The Darwin scanner does
not index these valid TTA files; the test verifies retained approved bytes,
an indexing pause with no completion credit, and conservative Stop. No application
decision infers the native platform from Python's host platform. Both tested native
builds reject valid TAK. Other builds/profiles remain unverified; see the
[codec/container matrix](../../../../docs/music-imports.md#formats-and-verification).
